SMART INTERVIEW COACH
REMAINING WORK AND IMPLEMENTATION ROADMAP
==========================================

AUTHENTICATION DECISION
-----------------------

Supabase is the sole authentication, database, storage, and application
backend platform. Firebase is not used. Gemini API calls remain server-side
through the Java backend, and the browser uses the Supabase anon key only.

Purpose
-------

This file documents the remaining work required to turn the current frontend
prototype into a complete production-ready Smart Interview Coach application.

MANDATORY TECHNOLOGY CONSTRAINT
-------------------------------

This project must be implemented as a JAVA FULL STACK application only.

Required technology direction:

- Frontend: HTML, CSS, and JavaScript.
- Backend: Java 17+ with Spring Boot.
- API layer: Spring Web / Spring MVC.
- Security: Spring Security with Firebase token verification.
- Database access: Spring Data JPA or Spring JDBC.
- Validation: Jakarta Bean Validation.
- Testing: JUnit 5, Mockito, and Spring Boot Test.
- Build tool: Maven or Gradle.

Node.js, Express, Mongoose, or a Node-only backend must not be used for the
production implementation. The existing JavaScript files are frontend browser
code only and are not a replacement for the Java backend.

Current implementation already includes:

- Responsive frontend design.
- Login and registration screens.
- Resume/manual onboarding UI.
- Local resume profile data storage.
- Dashboard, profile, reports, and My Interviews pages.
- Interview setup page.
- Working local interview room.
- Timer and question navigation.
- Local answer submission.
- Local score generation.
- Local report generation.
- Professional navigation and animations.

The current interview and authentication behavior is frontend-only and uses
localStorage. It must be replaced or connected to secure backend services.


1. RECOMMENDED FINAL ARCHITECTURE
---------------------------------

Frontend:

- Existing HTML, CSS, and JavaScript frontend.
- Use Firebase Authentication for identity.
- Use Firebase Google Sign-In.
- Use Firebase Phone Authentication with SMS OTP.
- Use Supabase for application data.
- Use a secure backend API for Gemini calls and file processing.

Authentication:

- Firebase Authentication is the identity provider.
- Firebase handles:
  - Email/password authentication.
  - Google authentication.
  - Mobile phone SMS OTP authentication.
- Store the Firebase user UID in Supabase.
- Never store raw passwords in Supabase.

Database:

- Supabase Postgres stores website data.
- Supabase Storage stores resumes and generated report files.
- Supabase Row Level Security protects user-owned records.

Backend:

- Java 17+ Spring Boot REST API.
- Gemini API calls must run on the backend.
- Firebase Admin SDK verifies Firebase ID tokens.
- Supabase service role key remains backend-only.
- Backend validates ownership before reading or changing data.

7. RESUME PROCESSING PIPELINE
-----------------------------

Registration flow:

1. User authenticates with Firebase.
2. User submits manual details or uploads a resume.
3. Frontend requests a signed upload URL or sends a protected multipart request.
4. Backend validates file type and size.
5. Backend stores the file in Supabase Storage.
6. Backend extracts text from PDF or DOCX.
7. Backend sanitizes extracted text.
8. Backend creates a resume record.
9. Backend sends sanitized text to Gemini.
10. Backend validates the AI result.
11. Backend saves the generated profile.
12. Backend sets profile_status to completed.
13. Frontend polls or receives completion status.
14. User sees recommended roles and interview topics.

Supported formats:

- PDF.
- DOCX.
- TXT.

Security:

- Reject executable files.
- Validate MIME type and extension.
- Limit file size to 5 MB.
- Generate random storage filenames.
- Do not use the original filename as a path.
- Do not expose public resume URLs.
- Use expiring signed URLs.
- Delete temporary files after processing.

IMPORTANT IMPLEMENTATION NOTE
-----------------------------

Firebase should be used for authentication only.

Supabase should be used for application data, interview records, reports,
profiles, goals, bookmarks, notifications, and private resume storage.

Gemini API calls must be made by the Java Spring Boot backend only. Never place
GEMINI_API_KEY in frontend files, localStorage, HTML, or public configuration.

The final deliverable must remain Java full stack: Spring Boot is the only
production backend, Firebase is used for authentication, and Supabase is used
for application data and storage. Node.js must not be introduced as a backend
replacement.
